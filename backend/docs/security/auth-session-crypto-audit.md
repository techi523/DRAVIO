**Strong points observed (not findings):**
- JWT secret is mandatory (min 32 chars) and startup fails hard without it — `src/config/env.ts:6`, `src/index.ts:55-57`.
- Refresh tokens are `crypto.randomBytes(64)` and stored SHA-256-hashed — `src/modules/auth/index.ts:24`, `src/modules/auth/repositories/auth.repository.ts:78-87`.
- Payment completion is CAS-guarded (`WHERE status='PENDING'`) inside one DB transaction with wallet credit — no double-callback crediting; idempotency key `ON CONFLICT DO NOTHING` — `src/modules/payment/repositories/payment.repository.ts:94-146`.
- Stripe webhook signed-body verification is real (`constructEvent` on raw buffer) — `src/modules/payment/providers/stripe.provider.ts:46-53`, `src/modules/payment/index.ts:31-62`.
- Admin role cannot be self-granted (register/OAuth/OTP restricted to BUYER/SELLER) and RBAC middleware rejects unauthenticated callers — `src/modules/auth/schema/auth.schema.ts:5-11,18-33`, `src/modules/admin/middleware/rbac.ts`.
- Audit metadata is sanitized server-side (`password|token|secret|api_key|authorization|cookie|session_token` → `[REDACTED]`) — `src/modules/compliance/pure/audit-events.ts:33-54`.

## 3. Prioritized fix list (files to change)

Order = severity × exploitability; each item names the concrete file to modify in this repo.

1. **Kill the user's own access path to "free money"/tooling endaround — A-05 (HIGH, cheapest).** `src/db/client.ts`: require `DATABASE_SSL_CA` in production and set `ssl: { ca, rejectUnauthorized: true }`. Also delete the anonymous `ws://0.0.0.0` assumption? (no — that's listen host, leave).
2. **A-18 — gate ISP activation + resolve actor from token.** `src/modules/isp/index.ts:126-132`: add `preHandler: [fastify.authenticate]`, take `customer_id` from `request.user.sub`.
3. **A-19 — remove `'default_secret'` fallback.** `src/modules/isp/index.ts:144`: throw if `ISP_<ID>_SECRET` unset (fail-fast like `JWT_SECRET` in `src/index.ts:55`).
4. **A-12 — make suspension/ban real.** In `src/modules/admin/middleware/rbac.ts` / `src/modules/auth/middleware.ts`: add user-status lookup (or Redis flag) in `authenticate` when caller has open admin action pending; plus `authRepository.revokeAllUserTokens(userId)` inside suspend/ban handlers (`users.controller.ts`).
5. **A-10 — delete the legacy refresh path.** `src/modules/auth/index.ts:206-214`: require `refresh_token`; remove access-token re-issuance. Add `config.rateLimit` on refresh.
6. **A-26 — bind session usage/end to owner.** `src/modules/billing/api/routes/usage.routes.ts` and `session.routes.ts:37-48`: fetch session, compare `userId`.
7. **A-14 — per-user + Redis-backed rate limits; register/refresh/withdraw limits.** `src/index.ts:73-76` config; add per-user `keyGenerator`.
8. **A-25 — commit counter in-DB.** `src/modules/billing/core/engines/byte-tracker.ts:118-123`: update `billing.sessions.bytes_used` inside the existing transaction and compute delta from DB; drop the pre-commit Redis read as the authority. Remove duplicate `updateCommittedBytes` call.
9. **A-17 — M-Pesa callback hardening.** `src/modules/payment/index.ts:64`: IP allow-list + return opaque provider ref instead of `checkoutRequestID` at `payment.service.ts:64-66`.
10. **A-06 — add password reset flow.** New routes in `src/modules/auth/index.ts` + table reuse of `auth.refresh_tokens`-style hashed one-time token; `auth.repository.ts`.
11. **A-08/A-09 — enumeration + OTP auto-account hygiene.** `src/modules/auth/index.ts:61-63`, `src/modules/auth/services/auth.service.ts:111-145`.
12. **A-16 — withdraw escrow/velocity.** `src/modules/billing/api/routes/wallet.routes.ts:51-100`.
13. **A-28 — real `adminId`.** Map across `src/modules/admin/api/*.controller.ts`.
14. **Low-cost hardening:** A-01 cost 12, A-04 `crypto.randomInt`, A-21 body-log scrub, A-22 FB header auth, A-12 access-token `jti` deny list (Redis).
